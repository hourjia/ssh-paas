一、设计原则（PaaS 版）
1.玻璃分层 = 平台架构分层 —— 视觉层级直接映射业务层级：服务器层（外框玻璃）→ 服务层（卡片玻璃）→ 配置/执行层（内嵌玻璃+实底层）。用户一眼看出"谁包含谁"。
2.左实右虚 —— 左侧导航和数据密集区（表格、日志、代码）用实底/低玻璃，右侧概览、状态、指标用玻璃。日志和配置代码永远不要放在强模糊玻璃上，可读性是 PaaS 的生命线。
3.状态即光 —— 服务运行状态通过玻璃上的光效表达：运行中=青绿呼吸微光、异常=琥珀/红描边辉光、停止=玻璃变灰降饱和。状态色 + 图标 + 文字三通道。
4.执行是"重动作" —— 「执行」按钮是全站唯一允许用强发光玻璃的地方，点击后进入 morphing 转场到执行控制台。
5.桌面端密度 —— 8pt 栅格，但组件更紧凑；玻璃层同屏 ≤ 12 个（桌面 GPU 更强，但表格行不要行行玻璃）。

深色玻璃的关键差异（对比手机浅色版）：填充透明度低（6-10%），模糊减到 16px，内高光弱化——深底上过亮的玻璃会变成"白雾"，显得廉价 。饱和度 140% 而非 180%，让背后光晕透出但不变艳。

1. 服务器卡片（绑定服务器）
两种形态：
概览卡（服务器列表页）：图标玻璃圆片 + 服务器名 + IP(Mono) + 状态胶囊 + 三指标 mini 图（CPU/内存/磁盘的玻璃进度条）+ 服务数徽章。
容器卡（服务器详情页）：Glass-Shell 大框，头部放服务器信息与全局操作（重启/解绑/添加服务），内部以 2-3 列网格排服务卡——容器比服务卡更"厚"（模糊更高、内高光更亮），形成玻璃嵌套的深度感。
绑定入口：虚线玻璃框 + 居中「+ 绑定服务器」，hover 时虚线流光滚动（唯一的装饰动效之一）。
2. 服务卡片（每服务器下多个服务）
结构：服务图标 + 名称 + 版本 chip(Mono) + 状态呼吸灯 → 资源迷你图（CPU/内存 sparkline）→ 底部操作行（配置 / 执行 / 日志）。
状态视觉编码：
运行中：左缘 2px 翠绿光条 + 图标微光；
异常：琥珀/红描边辉光 + 卡片顶部警示横条；
已停止：整卡降饱和（saturate(30%)）+ 灰玻璃。
服务卡三种密度：列表模式（单行紧凑）、卡片模式（默认）、拓扑模式（缩略玻璃节点 + 连线）。
3. 配置界面（服务详情 → 配置）
双栏布局：左侧配置表单（玻璃分组卡：基础配置 / 环境变量 / 资源限制 / 端口映射），右侧 实时预览面板（实底 YAML/Mono 展示最终配置，随表单联动高亮变化）。
表单控件统一 Glass-Control；开关、滑杆、下拉一套语言。
表单分组卡头部：分组图标 + 标题 + 折叠箭头；修改过未保存的分组右上角出现橙色小圆点。
底部粘性操作栏（Glass-Floating）：重置 | 校验 | 保存配置 | ▶ 执行 —— 执行按钮用强发光翠绿玻璃，是全页视觉焦点。
4. 执行（执行控制台）
点击「执行」→ 配置卡 morphing 展开为全屏执行视图（玻璃形变转场，400-500ms spring）。
执行视图三段式：顶部执行状态条（Glass-Shell：任务名、进行中动画、耗时 Mono 计数）→ 中部日志流（实底 #0A0F1A + Mono + ANSI 色 + 玻璃描边）→ 底部操作坞（Glass-Floating：停止/重试/导出日志）。
进度：玻璃管道式进度条（内部流光沿管道移动表示执行中）。
执行成功/失败：状态条整体泛翠绿/红辉光一次（0.6s），不做闪烁。
五、导航与全局组件
侧边栏：实底 + 右侧 1px 玻璃描边；选中项 = 玻璃胶囊 + 左缘品牌光条；折叠态 64px 只留图标。
顶栏：滚动后玻璃渐显（透明度 0 → 0.08）；右侧常驻全局执行指示器（有任务运行时显示玻璃呼吸灯 + 计数）。
面包屑：层级即架构（服务器 / 服务 / 配置），当前级用亮色 + Mono。
弹窗/抽屉：Glass-Shell 材质 + 背景 6px 模糊遮罩；表单弹窗宽度 ≤ 560px。
Toast：右上玻璃浮条，成功/失败带左侧色条。
空状态：玻璃框 + 线性插画 + 主操作按钮（如"绑定第一台服务器"）。
表格（执行记录、服务清单）：表头玻璃条，行 hover 玻璃提亮，行本身实底斑马纹——不要行行玻璃。
六、动效规范

场景	规格
页面/卡片入场	fadeUp 16px，stagger 60ms，350ms cubic-bezier(0.2,0.8,0.2,1)
配置→执行转场	玻璃卡 morphing 全屏，形变+模糊插值，450ms spring 
hover	卡片填充 +3%、描边辉光渐入 150ms；按钮 scale 1.01
按下	scale(0.98) 100ms
状态切换	光条/呼吸灯 300ms 交叉过渡
运行中	进度管流光循环、状态灯呼吸（2s 周期）——全站循环动画仅此两类
日志流	新行 fade+slide 150ms，不做逐字打字机（影响阅读速度）
七、可访问性与 PaaS 特有红线
1.玻璃上的正文对比度 ≥ 4.5:1；深色玻璃填充透明度是"上限受控、下限可调"——提供「降低透明度」偏好开关（iOS 27 也提供了透明度调节 ）。
2.Mono 区块零模糊：日志、代码、YAML 一律实底。
3.危险操作二次确认（解绑服务器、删除服务、覆盖配置）：确认弹窗中操作按钮红色实底玻璃，不用弱玻璃——危险动作要"重"。
4.执行按钮的破坏性变体：红色发光玻璃，与常规翠绿执行明确区分。
5.性能：backdrop-filter 在长列表/实时日志场景禁用；表格滚动时用静态层；will-change 只给转场元素。提供低性能模式（无模糊、纯半透明）。
6.状态不靠颜色单独传达：图标 + 文字（运行中/异常/已停止）+ 颜色三通道。
八、Do / Don't

Do	Don't
玻璃嵌套表达"服务器⊃服务"层级	所有卡片同一玻璃度，架构感全失
日志/配置用实底"屏幕"+玻璃相框	把代码放强模糊玻璃上
状态用光效、呼吸灯轻量表达	用大面积闪烁、警报红屏
执行按钮全站唯一强发光焦点	每个按钮都发光，焦点混乱
Mono 字体承载 IP/端口/命令/日志	用比例字体排配置代码
